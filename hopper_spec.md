## 1. Context and goal
University Aero Design course project (Hopper1) for a Preliminary Design Review. A lunar hopper flies from a site near the lunar south pole to a second fixed site, both given as lat/lon. An earlier study used an impulsive Lambert solution with a time-of-flight sweep for minimum Δv. This tool replaces it with a finite-burn optimal-control model that includes engine limits, path constraints, and a hazard-avoidance divert.

**Goal:** find the minimum-propellant trajectory, where the tank must cover the worst-case divert. Report Δv, the burn timeline, and propellant use.

## 2. Parameters (single source of truth)

  - `T_max`, `T_min`

- Pre-checks printed at startup:
  - T/W > 1 at wet mass.
  - Hover feasibility: `T_min ≤ m_dry·g_moon`. If it fails, warn that the engine cannot throttle low enough to hover.

## 3. Frames and geometry
- Moon-fixed body frame, with z along the spin axis and a spherical Moon of radius `R`.
- Site position: `(R + elev)·[cos(lat)cos(lon), cos(lat)sin(lon), sin(lat)]`. Never use lat/lon as optimization variables; the start is near the pole singularity.
- State position is stored as an offset from the start site, `r_abs = r_start + r`, so values stay at hop scale rather than Moon-radius scale.
- Altitude: `h = |r_abs| − R − terrain.height(r_abs)`. The PDR terrain model is `FlatTerrain` (returns 0). All elevations default to 0.
- Target local frame:
  - `up` = unit vector of `r_target`.
  - `downrange` = the direction from start to target, projected onto the horizontal plane at the target and normalized.
  - `left` = `up × downrange`.
- Divert sites: the target moved `divert_radius` along `+downrange`, `−downrange` (uprange), `+left` and `−left`, then projected back to the surface radius.

## 4. Dynamics (3-DOF, written once in CasADi; also used by scipy)
- State `x = [r(3), v(3), m]`. Control `u = [T_vec(3), Γ]`, where Γ is the commanded thrust magnitude.
- `r' = v`
- `v' = −μ·r_abs/|r_abs|³ + T_vec/m − 2ω×v − ω×(ω×r_abs)`
- `m' = −Γ/(g0·Isp)`
- Powered phases: `|T_vec|² ≤ Γ²` and `T_min ≤ Γ ≤ T_max`.
- Coast: no controls; `T_vec = 0` and `Γ = 0`.
- `Gravity` interface: `accel(r_abs)`. Implement `CentralGravity`; leave room for spherical harmonics later.
- Post-check: flag any powered node where `|T_vec| < 0.99·Γ`. This means the solver is discarding thrust it is paying fuel for, usually a sign that min throttle is too high to hover.

## 5. Phase structure
- Transcription: Hermite–Simpson collocation on normalized time `τ ∈ [0,1]`, with `dx/dτ = t_k·f(x,u)` and free duration `t_k` within its bounds. Put the transcription in a swappable class.
- Linkage: each phase's end state equals the next phase's start state.

| # | Phase | Duration | Phase-specific conditions |
|---|-------|----------|---------------------------|
| 1 | Vertical rise | free | start at start site, `v = 0`, `m = m_wet`; horizontal velocity = 0 at all nodes; ends at `h = h_rise` |
| 2 | Ascent burn | free | powered |
| 3 | Coast | free | engine off |
| 4 | Braking | free | powered; ends at gate |
| 5 | Hover | fixed = `hover_time` | `v = 0` at all nodes; altitude within `gate_alt_bounds`; horizontal position free. End state = **gate** |
| 6a–e | Terminal descent × 5 | free, each | start = gate; end at its site (nominal, uprange, downrange, left, right) at altitude 0 |

Phases 1–2 form one continuous burn (ascent burn), and phases 4–5–6 form another (descent burn). The nominal hop has 2 engine starts.

## 6. Constraints
Each constraint is a class with `apply(opti, phase)`, attached to phases through a list, so adding one later is a new class plus one line.

| Constraint | Applies to |
|------------|------------|
| Thrust bounds (§4) | all powered phases |
| `m ≥ m_dry` | all nodes |
| `h ≥ min_altitude` | ascent, coast, braking (not rise, hover, or terminal) |
| Glide slope: `h_rel ≥ tan(glide_slope_deg)·d_horiz`, relative to that branch's site | terminal descents |
| Tilt rate: `û_k·û_{k+1} ≥ cos(tilt_rate_max·Δt)`, with `û = T_vec/Γ` | within powered phases, and across the 1→2 and 4→5→6 junctions (not across the coast) |
| Touchdown: downward speed ≤ `td_vert_speed_max`, horizontal speed ≤ `td_horiz_speed_max` | final node of each terminal descent |

## 7. Objective
Maximize `z`, subject to `z ≤ m_final` of each of the 5 branches. This minimizes worst-case propellant, which sets the tank size. With constant Isp, it is equivalent to minimizing worst-case Δv.

## 8. Scaling and initial guess
- Nondimensionalize: length `L` = start-to-target distance, time `√(L/g_moon)`, mass `m_wet`, and thrust and force consistently.
- Lambert: implement a universal-variable Lambert solver in `lambert.py`. Do not use poliastro; it is archived.
  - Compute the impulsive surface-to-surface hop, sweeping TOF for minimum Δv. This is the "ideal Δv" baseline.
  - Seed the coast phase with the Lambert arc between the end of the rise and a point above the target.
- Seed the powered phases from rocket-equation burn-time estimates:
  - Γ = T_max for the ascent and braking burns, and Γ = m·g_moon for the hover.
  - Thrust direction along the required Δv, with states interpolated linearly.

## 9. Build order and acceptance checks
1. `params.py` and config: pre-checks print correctly. Unit tests cover the site and divert geometry; the four divert sites must be 100 m from the target and on the surface.
2. Dynamics: a coast propagated with scipy conserves the Jacobi constant; free fall from rest matches expectation.
3. Lambert baseline: report the minimum impulsive Δv and its TOF.
4. **Nominal only:** phases 1–5 plus the nominal terminal descent. It must converge, and its finite-burn Δv must be at least the Lambert Δv. Raising `T_max` ×10 should push Δv toward the Lambert value.
5. **Branches from a fixed gate:** hold the gate state from step 4 and solve each branch separately.
6. **Combined problem:** all phases and branches together, warm-started from steps 4–5.
7. Validation:
   - Re-propagate each branch's controls with `solve_ivp` and report touchdown position and velocity errors.
   - Mesh check: doubling the node counts must change worst-case Δv by less than 0.5%.
8. Outputs and divert-radius sweep (§10).

Target runtime for the combined solve: under about a minute on a laptop. Record actual times in `NOTES.md`.

## 10. Outputs (`results/`)
- `summary.json` and a console table:
  - Ideal Δv (Lambert).
  - Nominal finite-burn Δv, computed as ∫Γ/m dt.
  - Gravity and steering losses: nominal finite-burn Δv − hover Δv − Lambert Δv.
  - Hover Δv.
  - Divert Δv: worst branch terminal Δv − nominal terminal Δv. Name the worst branch.
  - Worst-case total Δv.
  - Propellant used, nominal and worst case.
  - Margin: `m_final − m_dry`.
- `burn_table.csv`:
  - One row per phase: start, end, duration, engine on/off, Δv, propellant.
  - Summary rows: ascent burn time (phases 1–2), descent burn time (4–6, nominal and worst branch), number of engine starts, total burn time.
- `trajectory_<branch>.csv`: t, r_abs, v, m, T_vec, Γ in the Moon-fixed frame, for STK cross-checking.
- Plots (PNG):
  - Altitude vs downrange, colored by phase.
  - Top-down view of the 5 branches around the target.
  - Throttle (Γ/T_max) vs time, with `min_throttle` marked.
  - Mass vs time.
  - Tilt angle vs time.
- Sweep: worst-case Δv and propellant vs `divert_radius`, with 100 m marked.
